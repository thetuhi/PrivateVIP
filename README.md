# Private VIP Istanbul

Marketing and enquiry site for a private travel agency in Istanbul: private
tours, Bosphorus yacht charters and VIP airport transfers.

There is no backend. The entire catalog is static data in the repo, and
enquiries reach the office through WhatsApp or email, the visitor sends the
message themselves, so nothing is collected server-side.

---

## Running it

```bash
npm install
npm run dev        # dev server on http://localhost:5173
npm run build      # regenerates sitemap.xml, then builds to dist/
npm run preview    # serve the production build locally
npm run lint       # ESLint
npm run images     # convert originals/ → optimised WebP in public/images/
npm run photos     # list every photo the site needs and which are still missing
npm run mock-images # fill empty photo slots with placeholders (dev only)
npm run fonts      # re-download the self-hosted webfonts
npm run sitemap    # regenerate sitemap.xml and robots.txt only
```

Environment variables are listed in `.env.example`. Both are optional:
`VITE_GA_MEASUREMENT_ID` (leave blank and no analytics script is ever
requested) and `VITE_SITE_URL` (used for canonical URLs and the sitemap).

## Stack

React 19 · Vite 8 · Tailwind CSS 3 · React Router 7 · i18next (EN / RU / TR) ·
lucide-react · sharp.

Motion is split between two libraries, each doing what it is best at:

- **GSAP + ScrollTrigger**, everything scroll-linked or timeline-based: the
  hero, parallax, image reveals, the pinned itinerary, split-text, the intro
  and the page-transition curtain.
- **framer-motion** (LazyMotion + `m`). React mount/unmount transitions, where
  `AnimatePresence` has no real GSAP equivalent: the mobile drawer, lightbox,
  FAQ accordion, cookie banner.
- **Lenis**, smooth scrolling, driven from GSAP's ticker.

Running both costs about 30 KB gzipped more than picking one. It is a
deliberate trade: rewriting the exit animations in GSAP would mean hand-rolling
unmount deferral in every one of those components.

## Photography

Photography carries this design.

Every slot currently holds a **mock placeholder**. Where no file exists at all,
`SmartImage` falls back further to a deterministic warm gradient with a faint
arch motif seeded from the filename, so a missing photo is never a broken
image icon. Dropping a real file in takes over automatically, no code change.

To clear the mocks and start from the gradient fallback:
`rm -rf public/images/{experiences,yachts,fleet,hero,home,about,brand}`

**To add photos:**

1. Put full-resolution originals in `originals/`, mirroring the public path:

   ```
   originals/experiences/imperial-istanbul/hagia-sophia-interior.jpg
   originals/yachts/classic-wooden-ketch/ketch-deck.jpg
   originals/hero/bosphorus-dusk.jpg
   ```

2. Run `npm run images`. Each file is rotated to its EXIF orientation, resized
   to a maximum of 2000px wide and written as quality-82 WebP into
 `public/images/…`, keeping the same folder structure. Re-running is safe,
   already-converted files are skipped.

3. Reference the `.webp` filename in the relevant data file.

`originals/` is git-ignored, so masters stay out of the repository.

**To see exactly what is needed**, run `npm run photos`. It reads the catalog
data and writes `PHOTO-MANIFEST.txt`, currently **61 slots**, each with the
exact path and what it is used for. Slots marked `CARD COVER` appear on listing
pages and are worth shooting first. Add a tour and its slots appear in the
manifest automatically; there is no second list to maintain.

## Editing content

| What | Where |
|---|---|
| Company identity, contact details, licence | `src/config/brand.js` |
| Tours and itineraries | `src/data/experiences.js` |
| Yacht fleet and charter types | `src/data/yachts.js` |
| Vehicles, transfer prices, service promises | `src/data/fleet.js` |
| FAQ | `src/content/faq.js` |
| Booking terms and privacy policy | `src/content/policies.js` |
| Interface strings (buttons, labels, errors) | `src/i18n/locales/{en,ru,tr}.json` |

**Catalog content is trilingual inline.** Every visitor-facing string in
`src/data/` and `src/content/` is an object:

```js
title: {
  en: 'Imperial Istanbul',
  ru: 'Императорский Стамбул',
  tr: 'İmparatorluk İstanbulu',
}
```

`localise()` resolves the active language and falls back to English, so a
partially translated entry degrades to readable rather than blank. Interface
strings work differently, they live in the three JSON locale files, and a key
added to one must be added to all three.

**To add a tour:** copy an existing block in `src/data/experiences.js`, give it
a unique `slug`, and add its photos. The catalog page, filters, detail page,
related-items list and sitemap all pick it up automatically.

Prices are per party, not per person, and the interface says so in several
places. If that ever changes, `experiences.priceNote` and `common.perParty` in
the locale files are the strings to update.

## Design system

Defined once in `tailwind.config.js` and `src/index.css`. Do not introduce
raw hex values in components.

**Nocturne palette**, warm near-blacks, never pure `#000`, with a single brass
accent. Contrast measured against the `ink-900` surface:

| Token | Hex | Contrast on ink-900 | Use |
|---|---|---|---|
| `bone` | `#F5F1EA` | 17.1:1 | Primary text |
| `bone-dim` | `#C9C2B6` | 10.9:1 | Secondary text |
| `bone-muted` | `#8E877C` | 5.4:1 | Tertiary text, still AA |
| `brass-500` | `#C0A062` | 7.7:1 | Accent, CTAs, active states |
| `ink-900` | `#0F0E0C` | base | Primary surface |

All five pass WCAG AA for normal body text; brass and the bone ramp pass AAA.
The site is dark-only by design, a luxury brand reads more coherently
committing to one look than splitting attention across two.

**Type**. Cormorant Garamond for display sizes only (its strokes thin out
below ~28px on a dark ground), Inter for everything else. Both cover Latin,
Latin Extended and Cyrillic, which is what EN/RU/TR needs.

Fonts are **self-hosted** (`npm run fonts`). The site makes no request to any
third-party origin, which is faster, since a render-blocking stylesheet on
someone else's domain sat in front of first paint, and it is what the privacy
policy promises.

## Motion

One easing and duration vocabulary, defined in `src/motion/gsap.js` and mirrored
by CSS custom properties in `index.css`, so a GSAP tween, a framer-motion
transition and a Tailwind `transition-*` on the same element all agree. Three
house curves: `luxe` (the default, long decisive tail, nothing bounces),
`precise` (pointer-driven, no overshoot), `veil` (masks and curtains).

Transform and opacity only, with one documented exception: the cursor ring
animates width/height so its 1px border stays 1px at every size, and is
`contain`ed so the layout work cannot escape the element.

| File | Responsibility |
|---|---|
| `motion/gsap.js` | Plugin registration, house easings, global defaults |
| `motion/MotionProvider.jsx` | Lenis ↔ GSAP ticker ↔ ScrollTrigger wiring; reduced-motion, pointer and intro state |
| `motion/lenisStore.js` | External store for the scroll instance (`useSyncExternalStore`) |
| `components/motion/SplitReveal.jsx` | Line-masked typography reveals |
| `components/motion/ScrollImage.jsx` | Clip-path reveal + parallax |
| `components/motion/StickyStory.jsx` | Pinned media panel with cross-fade |
| `components/motion/Cursor.jsx` | Custom cursor with contextual states |
| `components/motion/Magnetic.jsx` | Pointer-attracted CTAs |
| `components/motion/TiltCard.jsx` | 3D tilt with per-layer depth |
| `components/motion/PageTransition.jsx` | Navigation curtain + route prefetch |
| `components/motion/LoadingScreen.jsx` | First-visit intro |

The one hard integration is in `MotionProvider`: GSAP and Lenis both want to own
the frame loop. GSAP wins, Lenis is stepped inside its ticker, and ScrollTrigger
updates from Lenis rather than from the native scroll event Lenis has taken
over. Get it wrong in either direction and pinned sections drift a frame behind.

**Reduced motion is honoured at four levels**, so nothing depends on one guard
being remembered: Lenis is never constructed; `gsap.matchMedia()` reverts scroll
animations; `Reveal` and `SplitReveal` flatten to a short fade and skip
splitting entirely (keeping text selectable); and `index.css` neutralises
anything remaining as a backstop. The intro and the custom cursor never mount.

**Measured** on the production build, locally: first-contentful-paint 1.27s;
hero CTA readable at 2.75s on a first visit with the intro playing, 0.75s on
every visit after. The intro runs once per session, can be dismissed with any
click, key or scroll, and does not run at all under reduced motion.

To add a scroll animation, use the existing components rather than reaching for
`gsap` directly, they already handle reduced motion, cleanup and re-measurement
on resize. `useGSAP` (from `@gsap/react`) is required for anything bespoke: it
scopes selectors and reverts on unmount, which plain `useEffect` does not.

## Structure

```
src/
  components/         Navbar, Footer, SmartImage, Lightbox, …
    motion/           the animation layer (see the Motion section)
    icons/            local SVG glyphs (lucide v1 dropped brand icons)
 config/ brand.js, single source of truth for company identity
  content/            FAQ and policy copy
 data/ experiences.js, yachts.js, fleet.js, the catalog
  i18n/               i18next setup + locales/{en,ru,tr}.json
  motion/             GSAP setup, Lenis provider, framer-motion presets
  pages/              one file per route
 styles/fonts.css GENERATED, @font-face for the self-hosted webfonts
  utils/              localise, contact links, analytics, SEO head
  routes.js           lazy route chunks + hover prefetch
scripts/              images, mock-images, fonts, sitemap, photo-manifest
public/fonts/         self-hosted woff2 (committed)
public/images/        optimised WebP served to visitors
originals/            full-resolution masters (git-ignored)
```

Routes are code-split with `React.lazy` except the home page, which ships in
the initial bundle because that is where nearly all traffic lands.

## Deploying

The build output in `dist/` is fully static. Any host will do, with one
requirement: **all paths must fall back to `index.html`**, or a hard refresh on
a deep link like `/experiences/imperial-istanbul` returns 404.

- **Netlify / Cloudflare Pages**, handled by `public/_redirects`.
- **Vercel**, handled by `vercel.json`, which also sets cache headers.
- **Nginx**, add `try_files $uri $uri/ /index.html;`.

Set `VITE_SITE_URL` in the host's environment before building, or the sitemap
and canonical URLs will point at the default domain.

## Analytics and consent

Google Analytics is loaded **only** after the visitor accepts the banner. On
decline, no script is requested at all, not a blocked one, not an anonymised
one. With `VITE_GA_MEASUREMENT_ID` unset the banner does not render and the
module is inert. The privacy policy makes this claim, so `src/utils/analytics.js`
has to keep it true.

Events tracked: `page_view`, `contact_whatsapp`, `contact_phone`,
`enquiry_start`, `enquiry_submit`.
